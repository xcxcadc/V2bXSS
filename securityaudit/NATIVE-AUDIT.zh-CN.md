# 原生审计与本地规则清单

本次二开将三种来源分开处理，避免后台展示规则时改变原有处罚或转发逻辑。

| 来源 | 执行位置 | 后台展示与修改 | 命中证据 |
| --- | --- | --- | --- |
| 面板原有 `routes` 中的 `block` | 保留原生 Xray/sing 限制器行为 | `legacy_rules` 只读清单，来源固定 `panel_routes` | 现有核心日志；不会自动转换成新审计证据 |
| 节点配置的本地 `RuleListPath` | 默认只读；显式开启后在支持核心执行域名正则 | 独立 `local_rulelist` 只读清单；通过节点本地文件维护 | 原生核心可能输出拒绝日志；没有逐命中上报面板证据 |
| 新审计页的规则 | 独立审计引擎；按规则的 observe/block 执行 | 后台审计页维护 | 异步上报命中事件，包含认证用户 ID、目标、规则 ID、动作 |

原有代码只定义了 `RuleListPath` 配置字段，没有实际加载逻辑。本次补上可选读取，但不会因旧配置中已有这个路径就突然启用拦截。默认 `RuleListEnforce: false`。

## 配置和格式

在对应节点的 `ApiConfig` 中设置：

```json
{
  "RuleListPath": "/etc/v2bx-audit-test/local-domain-rules.txt",
  "RuleListEnforce": false
}
```

先用只读状态查看规则和加载错误。确认内容后，需要在节点配置显式设置 `RuleListEnforce: true` 并按原有配置重载方式生效。后台返回的规则不能改变这个本地开关或指定本地文件路径。

文件采用 UTF-8，每行一个 Go/RE2 域名正则，可以使用 `regexp:` 前缀。支持文件开头 BOM、空行、行首 `#` 或 `//` 注释；去重后保留首次出现顺序。例子只使用保留测试域名：

```text
# 精确域名
^example\.invalid$

# 含子域名
regexp:(^|\.)service\.invalid$
```

行中间的 `#` 不会被裁剪，因为它可能是正则内容。`protocol:` 不是本地文件支持的格式；应用协议规则仍使用原面板 `routes` 或新审计页。不能把 Xray JSON 路由、IP CIDR 或域名列表的其他方言直接当作该文件。无锚点的字符串按原生正则作包含匹配，建议针对域名使用明确锚点。

文件最多 256 KiB，最多 1000 条去重规则，每条最多 512 字节，独立清单 JSON 最多 60 KiB，并为错误信息与时间戳预留空间。完整文件先校验并编译；任一规则无效或清单过大时整个更新被拒绝，不会只加载一半。

## 热更新和失败处理

本地文件在现有节点配置轮询开始时检查；面板配置返回 HTTP 304、内容不变或暂时请求失败，都不会阻止本地文件检查。本地文件变化不重建节点、不重启核心、不删除用户，也不改变流量上报和在线统计的调用路径。未配置 `RuleListPath` 的节点不执行文件检查。

内容变化时先合并原面板规则和已启用的本地规则，完整编译后通过一个原子快照替换；连接线程只读这个快照，不等待磁盘或 HTTP。原面板新正则也改为安全编译，避免 `MustCompile` 导致进程崩溃；新面板规则无效时，在删除任何节点或用户前拒绝此次节点重载，保留原服务。

正常未变化文件每轮仅查询元数据，不重复读取内容。元数据比较包括文件身份、大小、修改时间和模式；不要刻意保留这些属性覆盖内容，应使用写临时文件后原子改名替换。只接受本地普通文件，拒绝符号链接、目录等；本地配置及所在目录应由受信任管理员管理。读取前后核对文件身份/元数据，检测到更新中变化则下轮重试。

坏正则、文件删除、读失败、超限文件均保留本进程最后一次有效规则、SHA256、最后加载时间以及原有执行状态，同时更新检查时间和安全错误码。错误不上传文件路径或正则内容。要明确清空本地规则，请保存空文件或仅含注释的文件；删除文件不会作为解除规则的指令。本地最后有效快照只保存在内存，重启后若文件仍无效，则只保留原面板规则，不会声称已加载上次的本地规则。

`local_rulelist` 上报包含：配置状态、实际开启状态、请求开关、核心支持状态、SHA256、检查/加载时间、安全错误码及只读规则数组。它不会被自动导入 `legacy_rules` 或新规则列表，也不会暴露节点的本地文件路径。未配置路径的旧节点不新增该字段。

## 核心边界

Xray 和 sing 沿用原生域名目标检测路径；可见目标为字面 IP 时，域名正则不会推断用户实际访问的网站。Hysteria2 只在现有安全请求回调中补充显式开启的本地域名正则，覆盖 TCP/UDP 请求并将本地规则版本计入 UDP 决策版本，因此规则变化后缓存目标会重新判断。Hysteria2 原先不支持的面板 `routes` 不会被这个改动悄悄开启；也不根据 UDP 猜测 QUIC 或其他应用协议。

本地原生规则不提供面板逐命中证据。需要在后台查询用户命中详情，应使用新审计页中明确的规则。所有来源都只能看到节点实际可见的连接目标和协议元数据，不能从 TLS 加密内容还原网页路径、页面内容或完整浏览历史。

## 本地验证

新增测试覆盖：默认只读、HTTP304 与接口故障时本地更新、坏文件保留有效策略、显式清空不删除面板规则、非普通文件与容量拒绝、面板坏正则在重载前拦截、并发读写时双源快照一致、只读上报独立且不泄露路径、HY2 的本地 TCP/UDP 拒绝及版本切换。

这些是自动化与本地回调验证；不代表已连接真实节点部署，或完成支付/注册/登录等面板端实机验收。发布包应重新构建并记录哈希，不能继续使用修改前的冻结二进制。
