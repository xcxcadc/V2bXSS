# 网络安全规则与验收范围

`example/security-audit-network-management.txt` 是可选的网络管理模板，不会自动改变现有节点规则。域名规则覆盖主域及子域；清单不是实时恶意网址情报库，也不能据此证明用户在挖矿。

在节点安全审计中批量预览，先选择测试节点，以停用或仅观察方式导入。确认影响后单独启用阻断。重复项保留已有操作和状态，不会自动覆盖。

| 输入 | 含义 | 限制 |
| --- | --- | --- |
| `domain:example.invalid` | 主域及所有子域 | 依赖连接中可见的目标域名 |
| `full:example.invalid` | 完整域名 | 不包含子域 |
| `regexp:(^|\.)example\.invalid$` | 域名正则 | RE2 可移植子集；不检查邮件正文、URL 路径或任意数据包 |
| `ip:203.0.113.0/24` | 目标 IP 网段 | 不把域名擅自解析后匹配 |
| `port:25` | SMTP 直投端口 | 同时影响合法直连邮件，不等同于识别垃圾邮件 |
| `protocol:bittorrent` | 内核识别的 BT 协议 | 依赖嗅探结果；原生 HY2 不支持应用协议识别 |

普通邮件服务、银行、测速和定位网站不能仅因出现在原始附件中就标成恶意网址。未提供经验证的恶意目标情报时，不生成虚构的恶意域名库。邮件地址正则、SMTP 关键字和 BT 数据包特征不能伪装为域名规则。

服务端逐行提示不可见字符和不兼容的数据包表达式，不静默改写；任何错误使整个导入批次不写入。格式转换、批内去重、已有规则去重均先预览再确认。

`tools/protocol-audit-check/run-sequential.sh` 在远端隔离环境逐项测试 13 个内核/传输组合，使用虚构用户与本地回显目标。覆盖 TCP/UDP 基线、IP 观察/阻断/解除、精确域名/子域/正则、目标端口、不匹配端口放行、流量及在线上报和用户撤销。通过这些测试不代表所有应用协议均能被识别，也不等于真实第三方支付验收。
